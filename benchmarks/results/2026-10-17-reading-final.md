# LiMR 阅读与解析收尾记录 · 2026-10-17

按最新范围停止 Windows 测试；最后最多五轮解析尝试实际执行一轮，无稳定收益，已放弃。保留此前已验证有效的改动，完成最终构建、包消费和 WSL 表格回归。功能改动已落地，仍有尾延迟，不能声称所有阅读场景都已肉眼无卡顿。

## 实现与架构分工

- LiMR 核心承担通用表格布局、图片预览、列表内翻译角标、异步文档会话、全局语义索引、窗口化阅读和加载状态。VS Code 负责文件、Worker、设置、资源路径与宿主消息适配，复用核心组件。
- 表格至少填满正文可用宽度，按实际字体、内容和已有角标计算列宽；量化同行及同列空白、换行、隐藏上下文和横滚成本。表头最多三行，正文行高按内容决定。短引用与角标、短句、正常单词和 E-Commerce 等复合词受保护；需要滚动时降低增加宽度的边际代价。
- 极长内容保留最小可读宽度；省略号后紧接既有注释角标。完整内容复用原侧栏或浮层，宽屏优先侧栏。横向裁字按布局问题修复：完整格子允许字形墨迹溢出，不用白色遮罩覆盖文字。详见[表格算法](../../docs/zh-CN/table-layout.md)。
- 图片点击展开能力由核心 Image/ImagePreview 提供；列表翻译角标留在 item 末尾。超长文档默认阻塞加载，可选渐进显示前缀并在全文完成后交接；已证明稳定的内容保留阅读位置和模块状态。任意插件不自动获得未经证明的增量处理能力。详见[大文档设计](../../docs/zh-CN/large-documents.md)。
- 宿主保留渐进期间的局部翻译选择，处理新的全局选择优先级及源版本变化，取消过期结果。

## 最后解析尝试与保留结果

保留的优化只对已登记、未修改的内置 GFM 语法生效：实际解析输入缺少表格必要标记时，跳过不可能成功的表格识别；未知扩展仍走原完整路径。单列表格、源码位置、实际预处理输入和完整 AST 保持原语义。

真实英文测试输入为 68 份保留原字节的 Gutenberg 原书，共 52,522,248 bytes / 51,889,576 UTF-16 单元，SHA256 `eb1629057b587f13b57cbb0d0eb54031254e9198baa13372f1741a80ecd2679a`。这是重复真实原书构造的约 50 MiB 负载，不是一部原生 50 MiB 小说。

| 自然 Worker 加载次序 | 基线全文就绪 | 保留优化后 | 改善 |
| --- | ---: | ---: | ---: |
| A → B | 10,757.8 ms | 9,928.5 ms | 7.71% |
| B → A | 10,812.5 ms | 9,820.3 ms | 9.18% |

两样本中位数从 10,785.2 降到 9,874.4 ms，约 8.44%。四场都通过完整数据图、位置、资源和交接检查；样本数有限，保留为本次对照结果。候选前缀文字几何约 195.7–197.5 ms 出现，此时字体仍在加载。

最后追加的一轮加强了表格分隔行必要条件，只用 WSL Node 独立进程做 A/B/B/A。结果为 15,967.97 / 15,770.85 / 16,258.39 / 16,053.52 ms；A/B 均值 16,010.74 / 16,014.62 ms，候选慢 0.024%，无稳定收益，未合入。类型检查、78 项相关测试及四场完整数据图相等验证通过，不能因此宣称性能改善。直接 Node 计时只包含文档解析与索引，不与上面的浏览器完整加载时间混用。第三方数组操作及无操作树遍历两个方向仅做设计审查，未作为额外实验轮次执行。

此前合成中文段落的 50 MiB 阻塞加载约 1.57–1.60 s；75 MiB 渐进前缀约 185–193 ms、全文约 2.30–2.33 s。这是较早 b16e 集成版本的独立负载证据，本轮未重新测量，不能和英文原书数字互相替代。

## 性能证据边界与未解决项

较早 b16e/common-v5 上，两个原始论文、三种对齐模式、两种侧栏、三次页面样本共 36 场 WSL 原生有头浏览器功能与环境检查有效；不是 36 次冷启动，也不是最终解析源码重新执行了整个矩阵。Windows 原生 Chrome 有有效单场及一个被放弃候选的 A/B；Windows VS Code 三项受控翻译功能测试有效，但不构成前台自然加载性能验收。最后 Windows KP 场在正式探针前失去前台而停止，0 个正式阅读探针。随后按用户要求停止 Windows 测试，不补做矩阵。

- 原论文 mount ready 为 194.9–330.8 ms；resize settled 为 208.9–240.4 ms，包含观察与静默条件，不是纯布局耗时。
- 快滚 P95 为 20.7–37.3 ms，跳转 P95 为 34.2–53.3 ms。仍有超过 50 ms 的帧；静止翻译切换最坏帧约 514 ms，2305 普通滚动个别帧约 490 ms。
- 定向 trace 和纯 HTML 控制说明部分长帧与原生 swap 等待相关，但没有证明驱动、WSLg 或所有长尾的统一根因。不同 GPU、平台、可见性数据不混合统计。
- 保留解析优化后，真实约 50 MiB 文本完整交接仍有 691.4–715.6 ms 最长帧和 678–710 ms 主线程长任务；历史合成 75 MiB 交接仍有约 390–415 ms 尾帧。这是明确保留的未解决项。

加载结束、早期可读、DOM 提交、帧调度和实际像素呈现是不同指标。本次按新的有界收尾要求完成，未将所有性能目标标为达成。
