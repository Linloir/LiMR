# Knuth–Plass 排版性能

[文档目录](README.md) · [English](../en/knuth-plass-performance.md)

LiMR 的 `typography="knuth-plass"` 提供段落级优化排版，将断行、词间距与连字符一起纳入求解，同时保留原文选区、复制和高亮交互。本文展示求解器吞吐，以及完整论文在桌面、窄屏和连续变宽过程中的阅读表现。

10,000 词合成段落的准备与求解中位数为 **6.826ms**，复用准备数据后为 **6.722ms**。完整论文的 KP 滚动 rAF P95 为桌面 **17.00ms**、窄屏 **17.10ms**；三种模式的浏览器验收共通过 **18/18**。

## 算法吞吐与宽度复用

求解器以 box/glue/penalty 表达内容，通过活动节点寻找段落的最小罚分路径，综合行松紧程度、相邻行差异和连字符。`prepareKnuthPlass` 复用宽度与伸缩前缀和及断点辅助数据，便于同一段落按不同宽度重新求解。

输入采用确定性的合成像素宽度，每项预热 3 次、采样 15 次；小输入批量执行并折算为单次调用。下表单位为 ms，显示中位数 / P95 / 最大值。“准备”指求解器前缀数据准备；造词、断词和字体测量属于浏览器集成阶段。

## 桌面与窄屏阅读

浏览器场景采用 23,713 个 UTF-16 代码单元的 scikit-learn 完整论文，运行于生产构建的 Playground，保留 Reader 目录、侧栏与插件。standard、CSS justify 和 KP 分别在 1380×1000 与 390×1000 的 Chromium 视口下运行，每组 3 个独立页面。

KP 按段落接近视口的顺序调度排版，批量执行字体测量和布局写入，并保留已排版节点供滚动复访。每页执行 3 轮、每轮 120 步的上下滚动；首轮经过新段落，后两轮复访已排版内容。

## 测量环境与复现

LiMR **1.3.0** · React **19.3.0** · Node **v20.19.5** · Chromium **156.0.8078.4**. 13th Gen Intel(R) Core(TM) i7-13700; 24 逻辑核; 31.2 GiB; linux 6.18.40.1-microsoft-standard-WSL2.

使用本地生产构建，按顺序执行，无 CPU 或网络降速；窄屏使用同一 Chromium 的视口模拟。P95 使用最近秩计算，算法表的 15 个样本中 P95 与最大值相同。

```sh
pnpm bench:kp
pnpm build:playground
pnpm preview:playground --port 4174
# 预览服务启动后，在另一个终端执行
pnpm bench:layout
```
