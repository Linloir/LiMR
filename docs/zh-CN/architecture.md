# 架构与行为

> 阅读提示：本文包含 LiMR 扩展语法和交互示例。部分内容在 GitHub 等普通 Markdown 阅读器中无法完整展示；前往 [GitHub Pages 文档](https://linloir.github.io/LiMR/#/docs/zh-CN/architecture) 可获得最佳阅读体验。

[文档目录](README.md) · [English](../en/architecture.md)

## 三层公开边界

1. core 管理原始 source、AST、块、标题、源内引用、诊断和选区坐标，无 React/DOM 运行时依赖。
2. React 层将文档、交互、布局、外部标注和资源状态连接到组件。
3. extensions 层使用同一套公开接口提供默认语法和交互；应用可以追加、替换或移除。

Doc 页面导航和 Playground 的保存、加载、语言菜单属于演示应用，不进入 LiMR 核心架构。

## 完整输入的加载管线

`DocumentSession` 拥有一次输入的读取/解码、解析、索引、传输、取消和最终文档状态；React 的 `AsyncReader` 把它接到 Reader。核心状态与 UI 分离，宿主可自行绘制进度。blocking 等最终快照，progressive 可先提供标明不完整的只读预览；完整性与是否挂载全部 DOM 分别管理。

内置且未改动的语法使用两遍有界解析：先由 Markdown 语法确认顶层安全边界并收集全局定义，再逐窗口生成 AST、释放临时 token/event 工作区，最后对合并树执行一次全文 transform。不会按任意字节切开列表、围栏、HTML、指令或公式。源标注发现与正文在输入完全相同时复用树与紧凑映射，行号索引共享；外部或被修改的解析钩子继续保留完整路径。

复杂大快照通过协商的分页 TypedArray 表示传输，去重字符串和对象形状并保留共享引用、Maps/Sets 与原始坐标。默认 Worker 在交付结果后、主线程分段还原前终止，以减少两端对象图重叠。满足独立性条件的纯段落另有块包传输路径。它们都是内部表示优化，公开的源文本、AST 与快照契约不变，也不提供任意插件的多线程分片解析或固定内存上限。

正文窗口、长目录窗口、标注区间索引以及按需计算的侧栏引用摘要降低阅读阶段的挂载与查询成本。完整树仍在内存；单个不可拆的大块、自定义语法、保留的媒体和全文打印仍可能占用较多资源。能力与回退条件见[大文档](large-documents.md)，复现数据见[加载与内存性能](loading-performance.md)。

## 追加解析

流式追加从末尾尚未稳定的顶层块回退，复用稳定前缀、行号索引和节点语义索引。持续增长的代码围栏可走字面量快速路径；收尾也可只重新解析尾部，不再一律全文解析。后到的 Markdown 引用/脚注定义、中间编辑、全文 transform 或更换扩展仍可能要求全文解析。长段落、列表和复杂未闭合标签仍有尾部重解析成本。

未闭合节点用 `incomplete` 标识，与所属顶层块仍在增长的 `pending` 区分。模块可渐进渲染或提供 `streaming.Loading`；不完整的语法头部与行内标记暂缓显示。增量动画只作用于新内容，临时包装节点在动画结束且原生选区离开后合并。代码在流式追加时保留已有文本节点，最终高亮也避开正在使用的选区。

公开的 source 始终保留原始输入。解析器内部为双冒号组件和未闭合语法补充解析标记，再通过稀疏偏移映射还原到原始 UTF-16 坐标；这些内部标记不会进入复制、标注或持久化数据。自定义 transform 必须维护坐标和局部性约定。源码中引用数据与应用 annotations 分开输入，在 React 视图层合并。

## 排版与源映射

标准模式默认使用浏览器排版。KP 在客户端按需加载：准备阶段缓存字形测量、断词、合法断点和前缀和，求解阶段运行 TeX 段落动态规划。视口附近的稳定段落优先排版，滚动离开后保留 DOM；宽度变化复用准备结果与文本容器。用户仍在选择的段落保留原生 Range，等待选区释放后再排版。源码坐标与标注保持不变，详细策略和测量见[样式](styles.md)与[KP 算法性能报告](knuth-plass-performance.md)。

原子内容的选区文本以完整源码序列化；同一选区里的普通文字保留渲染文本和显式换行。插件原子块的属性、子内容和嵌套原子节点服从外层整体选择契约。

## 状态与资源

配置数组/对象按不可变数据更新，静态配置保持引用稳定。滚动和 parameter 变化不需要重解析。一个 Provider 管理一个主正文；不同 Provider 的文档和标注请求隔离。

标注异步资源使用阅读器内有限缓存，消费者释放后可以取消无用请求。Shiki 的纯 token 结果使用模块级有限缓存；不应将其与用户标注数据缓存混为一谈。Mermaid 结果使用有限缓存，串行处理全局初始化与绘图，防止不同主题的阅读器相互干扰。库不提供模型服务、账号认证、数据库或自动保存。

## 退化行为

未知 HTML/自定义标签是惰性的原文；默认配置下未知指令仅渲染子内容。未知标注类型保留数据，但不显示角标、卡片或类型专属交互；注册对应模块后恢复展示。移除语法模块后，使用剩余模块重新解析未改写的原文。不完整语法恢复、transform diagnostics 和客户端渲染错误边界各有自己的适用范围，见[扩展开发](extensions.md)。

## 验证边界

仓库包含解析/坐标/SSR 单元测试、真实 Chromium 交互回归和 React 18/19 独立 npm 消费验证。浏览器测试中的远程媒体拦截、移动视口模拟和性能夹具不等于真实平台播放、移动设备验收或通用性能承诺。

## 原文编辑能力

解析与渲染不会隐式改写输入。standard 默认的 sourceAnnotations 把命名范围与定义解析成普通 Annotation，并提供通用 editSourceAnnotations 序列化器；类型、卡片和专用动作由模块注册。宿主提供 onSourceChange 后，默认任务/高亮和模块动作才可通过 editSource 提交同一 revision 下的原子修改。核心负责偏移与重叠校验，默认或自定义处理器负责格式序列化，宿主或接入模块负责接受、文件保存与撤销。源内标注沿用同一侧栏、浮层和工具栏，外部 annotations 的存储通路保持独立，无需额外编辑器组件。
