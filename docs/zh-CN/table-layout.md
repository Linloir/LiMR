# 表格布局

[文档](README.md) · [English](../en/table-layout.md)

LiMR 的 core 负责列宽与行高决策，React 适配层测量实际渲染内容，溢出内容复用现有注释 UI。Playground 与 VS Code 使用同一个组件；表格算法独立于段落对齐及 KP 排版。

## 先选择阅读策略

默认 Reader / AsyncReader 已包含自适应表格。算法根据实际字体和内容分配列宽、选择行高，避免一格长文拉高整行；截断内容通过 `…` 后的标注入口查看，也能在原格展开。Markdown 源码保持完整。

| 场景 | 推荐方式 | 行为 |
| --- | --- | --- |
| 论文、对比表、长短内容混合 | 保留默认 `tableLayout` | 内容自适应宽高、必要的横向滚动和完整内容预览 |
| 更看重浏览器原生尺寸、无需溢出卡片 | `tableLayout: false` | 原生表格布局与横滚，无测量、裁剪和派生预览 |
| 只想调整宽高保护限值 | `{ maxColumnWidth, maxRowHeight }` | 保留默认算法，只调整明确限制 |
| 需要不同列宽/行高策略 | `{ algorithm }` | 替换计算函数，复用测量、缓存与预览 |
| 需要完全不同的 DOM 或测量方式 | `rendererOverrides` | 由自定义视图实现对应契约，见[扩展开发](extensions.md) |

表格策略不受 `typography`、代码块换行或大文档窗口化开关控制。单张超大表仍可能创建大量 DOM；窗口化整个文档并不等于虚拟化表格行。接入示例见[快速开始](getting-started.md#调整阅读策略)，算法细节放在本页后半部分。

## 溢出、源码与配置

是否截断按完整文字宽度判断，测量时暂时排除后缀；紧急换行规则不随截断状态改变，避免已有角标反过来制造或维持溢出。

被裁剪的格子保留原来的源码绑定 DOM。独立后缀轨道为紧邻的“省略号＋注释角标”预留真实空间，不用白色遮罩覆盖字形。完整格子保持溢出可见，允许斜体、重音等字形的墨迹略超出测量的排版前进宽度。每张表批量注册视图注释，宽屏使用原有侧栏，窄屏使用原有浮层和卡片；可阅读完整内容、复制 Markdown 或在原格展开。可视预览不注册重复源码锚点，派生注释不写入源码，也不参与 Markdown 导出或源注释编辑。

```tsx
<Reader
  source={markdown}
  parameters={{ tableLayout: { maxColumnWidth: 720 } }}
/>
```

`maxColumnWidth` 单位为 CSS 像素，保护文字区域；填满正文所需的列轨道可以超过它。`maxRowHeight` 是可选的显式像素保护上限，不设置时按内容决策行高。自定义集成还可通过 `fontSize`、`cellPadding` 覆盖适配层测量。自定义内容的字体或媒体变化应产生正常 DOM 变化或 load 事件；极大单元格仅精确测量前缀，尾部使用估算。

回归覆盖稀疏表、单列表、引用／评述表、19 列表在 500、760、1100 像素下的布局，以及罕见短语、连字符表头、长 token 临界换行与非空逐行字形计数、真实引用角标、字形与后缀不重叠、富文本完整预览、源码选区、隐藏翻译区域、密集行、打印与视图注释注册幂等。纯算法测试之外还检查浏览器与实际文章截图；这些证据不代表任意自定义单元格都具有相同外观或性能。

## 关闭或替换布局算法（1.3.1）

这是默认表格渲染器内置的能力，无需额外安装布局模块。省略 `parameters.tableLayout` 或传 `{}`，继续使用 1.3.0 的 `layoutTable` 算法、测量与有界缓存；原有数字配置保持兼容。

```tsx
import { Reader } from '@linloir/limr';

export function NativeTables({ source }: { source: string }) {
  return <Reader source={source} parameters={{ tableLayout: false }} />;
}
```

`false` 保留 GFM 表格、对齐、富文本、源码选区和原文注释，使用浏览器原生表格布局与横向滚动。此模式不挂载 LiMR 的表格测量、布局观察器、固定列宽、行高裁剪或派生溢出预览。切换模式会重新挂载表格视图并释放旧的溢出注释；不要依赖切换前的 DOM 焦点或选区继续存在。修改参数不重新解析源码。`Reader`、`AsyncReader`、`Markdown` 和 `DocumentProvider` 均支持该参数。

通过 `algorithm` 替换计算函数，也可在普通模块的 `parameters` 中注册默认配置：

```tsx
import { Reader, defineExtension, layoutTable, type TableLayoutAlgorithm } from '@linloir/limr';

const compactLayout: TableLayoutAlgorithm = input => layoutTable({
  ...input,
  options: { ...input.options, maxColumnWidth: 560 },
});
const plugins = [defineExtension({
  name: 'compact-table-layout',
  parameters: { tableLayout: { algorithm: compactLayout } },
})];

export function Article({ source }: { source: string }) {
  return <Reader source={source} plugins={plugins} />;
}
```

算法可完全自行实现，不必调用 `layoutTable`。它在浏览器主线程同步接收 `TableLayoutInput`：实际测量的 `rows`、CSS 像素 `availableWidth` 与包含测得字号/水平内边距的 `options`。输入由缓存持有，须视为只读；返回完整 `TableLayoutPlan`：

- `widths`、`contentWidths`：每列一个正数，均包含水平内边距；文字窗口可小于列轨道。
- `heights`：每行的内容高度，不含内边距；`clipped` 与单元格矩阵一致，表示需要限制高度的单元格。自定义算法的表头高度也会被采用，正文仅对标记为裁剪的格子应用行高限制。
- `width` 为列轨道宽度之和；`scroll` 表示横向滚动；`cost`、`evaluations` 为数值诊断信息，不计算时可设为零。

自定义算法继续复用测量、宽度方案缓存、实际 DOM 溢出检查与完整内容预览。保持函数和配置引用稳定；状态变化时传入新配置以失效缓存。算法必须同步、无副作用并返回有效方案；异常不会被静默替换为默认方案。SSR 不调用需要浏览器测量的算法。`layoutTable` 与算法类型也可从 `@linloir/limr/core` 导入；React 层公开 `TableLayoutConfig`。

优先级为单表 `MarkdownTable.options` > 宿主 `parameters.tableLayout` > 最后一个提供该参数的扩展 > 内置默认值。整个配置值替换，不逐字段合并；宿主传 `{}` 可覆盖插件并恢复内置算法，传 `false` 可关闭，省略则继承插件。插件同样可注册 `tableLayout: false`。这些是视图参数，不需要改写 GFM 解析模块或向 Worker 传递算法函数。若还需替换测量和整个表格 DOM，使用现有 `rendererOverrides`，见[扩展开发](extensions.md)。

默认路径没有新增逐单元格校验、测量、观察器或评分步骤；仅在表格入口选择原生或测量布局，并在已有缓存未命中时调用选定算法。自定义算法自身的性能由插件负责。

## 默认算法的约束与测量

表格总宽至少填满正文可用宽度。列宽由算法明确指定：先把剩余宽度用于减少换行与截断，再按内容权重分配。因此单列表格也能填满正文，同时保留文字区域的最大可读行长。

测量使用实际字体、字重、字距、行内边距及原有角标几何尺寸，不把 Markdown 源字符数当作宽度。短引用与其角标作为不可分整体。正常单词与 `E-Commerce` 等适度长度的连字符词建立可读宽度下限；两行能够完整呈现的短句受到保护。表头最多三行；正文没有默认六行或八行上限。

字宽缓存按所属 `Document` 隔离；字体开始加载、加载完成或失败时会失效，即使加载期间表格已卸载也不会在重新挂载时沿用旧字宽。普通宽度变化仍复用字体测量。此机制依赖字体加载事件，不自动检测没有加载事件的同步字体集合或 CSSOM 修改。

极长 token 的可读宽度下限包含按实际字形测量的前缀（八个拉丁字素或四个 CJK 字素），再加省略号与真实溢出角标的宽度。它仍服从配置保护上限，避免异常长内容在后缀旁只剩一个像素的文字轨道。

断行机会以 [Unicode 断行规则](https://www.unicode.org/reports/tr14/)为基础，再保护短复合词及与前文相连的角标；不修改原始源码或 DOM 文字。布局后检查实际 DOM 溢出，以处理字体塑形、嵌入内容和浏览器行盒与估算的偏差。

## 量化目标与有界搜索

设 `w[j]` 为文字区域宽度，`d[i,j]` 为该格完整换行高度，`H[i]` 为候选行高，`n[i,j]` 为自然单行宽度，`e` 为字号。近似目标包含：

- 同行空白：`Σ w[j] × max(0, H[i] − d[i,j]) / e²`。单个极高单元格须承担给同行短内容增加的空白面积。
- 同列空白：`0.14 × Σ max(0, w[j] − n[i,j]) × min(H[i], d[i,j]) / e²`。增宽一列须承担其中短内容新增的横向空白。正常段落换行后的参差行尾不计作这种外部代价。
- 上下文损失：隐藏行数除以可见行数的平方根，并对每个截断单元格增加一次起始代价。表头损失权重更高；原本两行即可完整呈现的短内容，不允许被行高优化器进一步裁短。
- 纵向阅读高度、额外表头行数、不可分短 token 溢出及横向滚动距离。

横滚包含一次启用代价，以及较低的额外宽度边际代价。因此普通表格优先换行；已经需要横滚的表格，可以给密集列更多宽度来明显降低行高。如果一行多数格仍极高，还会比较四个同时增宽的候选方案，因为只增宽一个格不能降低其他密格决定的行高。

列宽候选上界依据内容画像调整：大量长文本所在列可以比“多数勾号、仅一个极长值”的列更宽。配置保护上限仍约束文字区域；默认保护值随宽正文从 `48em` 适度增长至最多 `64em`，它是边界而非目标宽度；显式配置的上限保持精确。行高候选来自实际内容需求与几何中间值，不来自固定行数。

对于完整、单个长 token 的表头，还会进行有界的临界换行检查：按测得的字素前进宽度估算两行、三行阈值；若阈值只比自适应上限大至多 `1em`，允许向上吸附到半像素精度，但不能超过显式保护值。这避免上限恰好略低于真实换行边界时，末行只留下一个字母。每个 token 最多检查 96 个字素，每表最多 768 个，每种行数至多十轮可行性检查；原子内容、只测得部分的内容、极长内容或前进宽度不单调的塑形情况跳过这项细调。

优化阶段至多使用 40 个代表行、每列 18 个宽度候选、三轮坐标改进与两轮有限宽度交换；另比较内容均衡的满宽初值。评分至多 768 次，超过 48 列时降至 96 次，额外空间分配至多 256 次试探。每行至多 24 个高度候选。内容画像与最终逐行决策仍需遍历表格，不能据此认为百万格表格是常数时间，也不会自动虚拟化表格 DOM。每个被测试宽度的换行结果会缓存，列宽方案及短文字测量也使用有界缓存。

这是一种确定性的候选近似优化，不是 Knuth–Plass 段落动态规划，也不保证全局最优。[CSS 2 自动表格布局](https://www.w3.org/TR/CSS22/tables.html#auto-table-layout)及 [CSS Tables 草案的宽度分配模型](https://drafts.csswg.org/css-tables-3/#width-distribution-algorithm)提供了内在尺寸的参考；LiMR 额外考虑行列空白代价、短内容可读性及显式完整内容预览。后者仍是草案，不作为浏览器规范一致性声明。
