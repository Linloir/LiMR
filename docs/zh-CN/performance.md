# 渲染器性能报告

[文档目录](README.md) · [English](../en/performance.md)

LiMR 面向流式输出、长文阅读和交互式标注，在提供丰富 Markdown 能力的同时保持轻快的更新与阅读体验。以下数据覆盖完整文档挂载、逐块流式更新，以及开启默认模块和动画的实际阅读。

## 性能概览

- **长文档约 1.07 秒挂载**：完整渲染 877,782 个 UTF-16 字符。
- **3/4 类流式场景累计同步耗时最低**：与相同输入下的 react-markdown、Markstream 对比，涵盖混合内容、代码、表格和长段落。
- **丰富内容流式更新 P95 为 4.0ms**：保留默认模块、动画、样式与字体。
- **桌面、长文和窄屏阅读 9/9 通过**：覆盖首屏内容、滚动及文档跳转。

## 长文档挂载与资源占用

从短文到约 87.8 万字符的长文，全文挂载保留完整正文 DOM，支持浏览器原生选区和文档定位。以下同样使用五次独立页面，列出挂载中位数 [最小–最大]，单位 ms。

| 文档 / 字符数 | LiMR | react-markdown | Markstream |
| --- | --- | --- | --- |
| 短文档 / 8,700 | 21.00 [19.30–21.20] | 17.30 [16.60–18.10] | 15.40 [14.70–16.50] |
| 中等文档 / 87,381 | 117.10 [113.40–119.90] | 106.10 [104.50–107.10] | 91.40 [90.50–96.50] |
| 长文档 / 877,782 | 1070.50 [1036.00–1083.60] | 1095.60 [1085.50–1130.10] | 733.00 [722.50–753.30] |

同一长文档下的保留 JS 堆与正文 DOM：

| 渲染器 | 增量 JS 堆 MiB | 正文元素 |
| --- | --- | --- |
| LiMR | 76.87 | 76014 |
| react-markdown | 13.09 | 36001 |
| Markstream | 126.33 | 152001 |

JS 堆是显式 GC 后相对于预热空页面的增量；DOM 统计正文元素。

## 完整功能下的阅读体验

丰富流式场景同时包含 TypeScript、Python、JSON、公式、表格、任务列表和本地图片。LiMR 保留默认模块、动画、样式与字体；每库运行三个资源预热页面，并检查章节与特殊块内容。

| 渲染器 | 内容验证 | 累计同步耗时 ms | 更新 P95 ms |
| --- | --- | --- | --- |
| LiMR | 3/3 | 188.90 | 4.00 |
| react-markdown | 3/3 | 1122.20 | 17.10 |
| Markstream | 3/3 | 202.50 | 3.30 |

LiMR 的阅读场景覆盖桌面 1440×900 和窄屏 390×900。长文包含 240 个章节、240 个代码块、480 个公式和 30 张本地图片；每种场景使用三个冷浏览器上下文，完成上下滚动以及中部、末尾、顶部跳转。

| LiMR 阅读场景 | 内容验证 | 首个正文可读 ms | 滚动帧间隔 P95 ms |
| --- | --- | --- | --- |
| 桌面阅读 | 3/3 | 261.70 | 16.70 |
| 桌面长文 | 3/3 | 1565.30 | 33.30 |
| 窄屏阅读 | 3/3 | 258.40 | 16.80 |

首个正文可读由 DOM 与两次 rAF 确认，从页面导航开始计时；滚动 P95 统计 rAF 间隔。窄屏使用 Chromium 视口模拟。

完整输入的 Worker 加载、渐进预览、50/75 MiB 峰值与空闲内存，以及真实论文交互矩阵见 [加载与内存性能](loading-performance.md)。该报告单独计量完整管线，不与上述同步提交耗时混用。

## 交互式选区与标注

在 2,000 节长文和 1,000 行代码中连续拖选，LiMR 随选区变化更新高亮覆盖层。每种情况在三个字体就绪页面上执行连续鼠标移动。

| LiMR 场景 | 帧间隔 P95 ms | 覆盖层更新 P95 ms |
| --- | --- | --- |
| 长文拖选 | 50.00 | 63.70 |
| 代码拖选 | 16.80 | 20.50 |

覆盖层更新从 selectionchange 事件计至 DOM 变更。段落排版能力及相关数据见 [Knuth–Plass 性能报告](knuth-plass-performance.md)。

## 测试方法与复现

LiMR **1.3.0** · React **19.3.0** · Node **v20.19.5** · Chromium **156.0.8078.4**. 13th Gen Intel(R) Core(TM) i7-13700; 24 逻辑核; 31.2 GiB; linux 6.18.40.1-microsoft-standard-WSL2.

react-markdown **10.1.0** · Markstream React **2.0.19**.

同机 Chromium、生产构建、无 CPU 或网络降速。版本由锁文件固定；表格使用最近秩分位数，除另有说明外取独立运行的中位数。三至五次采样用于描述这些输入下的表现。

| 配置 | LiMR | react-markdown | Markstream |
| --- | --- | --- | --- |
| 全文与受控流式 | Markdown + gfm; interactive=false; streamEffect=false | remark-gfm | 关闭虚拟化、批处理、延迟渲染与动画；原生 pre |
| 丰富内容 | 默认模块、动画、样式与字体 | remark-gfm + remark-math + rehype-katex + async Shiki | 默认 MarkdownRender；stream-diffs 与 KaTeX |

受控场景使用相同中性 CSS；丰富场景采用各自集成的样式、字体和加载策略。计时外检查正文结构与文本。原始数据提供逐次计时、资源和配置详情。

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm bench
```

原始数据: [renderers.json](../../benchmarks/results/renderers.json) · [selection.json](../../benchmarks/results/selection.json). [基准说明与单项命令](../../benchmarks/README.md).
