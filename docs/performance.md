# 性能测量

日期：2026-10-12。环境为 Intel Core i7-13700、WSL2/Linux、Node 20.19.5、Chromium 156.0.8078.4。React 19 production build；对照为 react-markdown 10.1.0 + remark-gfm 4.0.1。

以下是本机固定夹具的实测值。静态渲染与基线接近；流式追加减少了明显的重复工作。几个百分点的静态差异不应解读为所有设备和内容上的胜负。

## 浏览器

双方都渲染同一份 GFM：标题、强调、链接、行内代码、列表和表格，使用相同排版样式。LiMR 开启正常交互和原文映射能力。这里只比较正文，不把目录、侧栏等基线不具备的 UI 算进去。

每组运行三次、取中位数；每次用独立页面，先预热并等待字体，交替运行两个渲染器，避免上一组 DOM/内存影响下一组。计时范围是同步 React 提交和一次强制布局；不计网络下载、异步重资源加载、帧间空闲时间及后续观察器工作。

| 场景 | LiMR | react-markdown |
| --- | ---: | ---: |
| 87,381 字符，200 节，首次挂载 | 108.1 ms | 109.8 ms |
| 877,782 字符，2,000 节，首次挂载 | 1,249.2 ms | 1,280.0 ms |
| 34,860 字符，256 字符/次，138 次提交，累计同步时间 | 287.8 ms | 1,844.9 ms |
| 同一流式场景，单次提交 P95 | 2.8 ms | 23.6 ms |

本次流式累计同步时间约为基线的 **1/6.4**。末次提交执行最终完整解析，也包含在统计内。流式单次最大值仍为 34.0 ms，不能将 P95 解读为每一帧都小于 16 ms。

长文夹具最终 DOM 元素数：LiMR 40,001，基线 36,001。差异主要来自表格滚动容器和原子节点；普通段落、标题和文本不再依赖额外包裹层。未使用虚拟化，浏览器仍能搜索、选择和打印整个文档。

原始样本：[browser.json](../benchmarks/results/browser.json)。

## Node / SSR

core 对照为同版本 mdast-util-from-markdown + GFM。core 除解析外还生成标题、脚注、角注、区块和原文元信息。SSR 对照使用等价 GFM 功能；没有把未加载的代码高亮或公式冷启动算成渲染优势。

| 场景 | LiMR | 对照 |
| --- | ---: | ---: |
| 87,381 字符，核心处理 | 114.64 ms | 112.79 ms |
| 877,782 字符，核心处理 | 2,371.85 ms | 2,413.30 ms |
| 87,381 字符，SSR | 109.64 ms | 115.60 ms |
| 877,782 字符，SSR | 2,369.39 ms | 2,586.03 ms |
| 34,860 字符，137 次核心追加及收尾，累计 | 159.99 ms | 2,646.48 ms |

核心追加对照每次重新解析整个前缀。不同组分别预热，GC 和 JIT 会影响数值，因此不能把“核心处理”和“SSR”两行相减当作精确的 React 渲染成本。原始区间：[node.json](../benchmarks/results/node.json)。

## 实现要点和边界

- 追加时回退到末尾尚未稳定的顶层区块。先前的 Markdown 定义作为解析环境；新定义影响前文时完整校正；生成结束时完整解析。
- 源文本从不预处理改写，坐标是原始 UTF-16 偏移。普通文本在真正选择时才建立 DOM 文本节点到源码的映射；装饰和自定义布局按需采用显式绑定。
- 区块和未变化的目录保持引用稳定；交互、布局与文档分开更新。滚动不会触发重新解析。
- 代码接近视口时加载所需语言/主题；流式代码暂停后高亮。公式和视频分别按需加载或点击加载。
- 角注的缓存按阅读器隔离。浏览器测试覆盖了预览切换展开时复用同一请求、再次打开命中缓存、数据变更后重新请求；默认渲染没有第三方 CDN 请求。

尾部若是非常长的单个代码块、列表或未闭合标签，重新解析该区块的成本仍会增长。全文 transform、修改中间内容、引用定义变化和收尾都会触发完整解析。这不是任意语法、任意编辑模式下的常数时间增量解析器。

这里的性能数据没有覆盖大型公式集、Shiki 冷启动、密集外部注释、第三方插件、完整 Reader 布局或真实移动设备。相关功能另有交互验证，但不能从这些 GFM 数据推导出它们的性能承诺。

## 复现

在仓库中运行，测量时不要并行运行构建或其他基准：

```sh
NODE_ENV=production pnpm bench
pnpm exec vite build
pnpm exec vite preview --host 127.0.0.1 --port 4174
# 另一个终端：
pnpm bench:browser
```

脚本及夹具位于 `benchmarks/` 和 `playground/benchmark.tsx`；结果写入 `benchmarks/results/`。
